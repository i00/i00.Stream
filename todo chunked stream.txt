18. IndexOffset still exists even though metadata is paged 
The header stores IndexOffset, and many operations use _IndexOffset, but the actual current metadata system is paged via metadata root, index pages, and directory pages. [_ChunkedStream | Txt], [ChunkedStr...m.Metadata | Txt] 
Possible reason: _IndexOffset represents the data-area boundary rather than a flat index table location now, or it preserves compatibility with an earlier flat-index design. 
Why I’m unsure: the name IndexOffset feels legacy. In multiple places it behaves more like DataAreaEndOffset or MetadataBoundaryOffset. If the flat index is gone, renaming internally would make the design easier to reason about.
